# 开发、测试与发布

## 依赖分层

- `pip install -e '.[dev]'`：核心仿真、API、测试；无需 GPU、私有数据或学习权重。
- `pip install -e '.[dev,geo]'`：增加栅格和坐标导入。
- `pip install -e '.[dev,geo,navigation]'`：增加可选 PyTorch 学习、Numba 加速与视频工具；CPU/GPU 的 PyTorch 安装应按所在机器选择。
- 前端使用 `npm ci`，锁文件纳入版本控制；Node.js 20+。

不要通过修改实验脚本的固定输入来“修复”核心测试；不要把数据下载或长时间训练加入普通测试。

## 扩展位置

新增通用物理功能应修改公共 `unified/` 模型，并补齐 schema、数值检查、产品元数据与独立测试；数据集适配器只负责读观测/资料和输出配置，不再创建一个专用生产仿真器。

API、CLI 与 Python 使用同一 Session。新接口需要覆盖异常、取消、输出形状和来源记录；新近似应明确适用频率、距离、角度、时间尺度。

```bash
python -m pytest
python scripts/verify_configuration_matrix.py --output .runtime/acceptance
cd frontend
npm ci
npm run build
```

功能矩阵检查所有公开采集模型的配置入口与原生输出；自动化测试检查物理/数值与接口行为。二者都不是实测保真认证。可选依赖测试跳过数应在交付中明确报告。

## 仓库边界

发布核心代码、配置、测试、前端源码/锁文件和当前维护文档。`.runtime`、虚拟环境、数据、权重、历史报告副本、私有会话统计和构建产物不入库。旧实现作为明确命名的回归参考保留；未证明无引用的代码不随意删除。

## 服务安全

这是单用户科研工具，没有账户系统、鉴权或多租户隔离。默认仅监听 `127.0.0.1`。内网访问可显式使用 `--host 0.0.0.0`；不要直接将没有访问控制的服务暴露到公网。对外部署需自行配置认证、TLS、访问限制、磁盘/计算配额。

上述安全默认值指当前 `radar-platform serve`。旧兼容入口 `python -m radar_platform` 为保持冻结实验和历史行为，仍沿用原来的监听配置（未设环境变量时为 `0.0.0.0`）；新部署不要使用旧入口。

`RADAR_DATA_ROOT` 控制外部数据位置，`RADAR_RUNTIME_ROOT` 控制结果存储；不要将二者设为敏感目录。大场景仍可能需要分钟级计算，结果播放不等于物理时间实时仿真。
